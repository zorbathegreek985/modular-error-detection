# Exact Analytical Detection-Profile Engine

## Scope

The package module `modular_error_detection.profiles` computes exact profiles for the existing plain-residue model. It accepts a decimal modulus `m>1`, uses position `k>=0`, and distinguishes `substitution` from `transposition`. It does not enumerate source strings and does not alter the historical sweep or its generated artifacts.

## Established mathematics

For digit difference `d=b-a` in `{-9,...,-1,1,...,9}`, the value changes are `d*10^k` for a substitution and `9*d*10^k` for an unequal adjacent swap whose lower digit is at `k`. Gcd cancellation gives the reduced divisor

```text
h_s(m,k) = m/gcd(m,10^k)
h_t(m,k) = m/gcd(m,9*10^k)
```

An event is undetected iff the relevant reduced divisor divides `d`. For positive integer `h`, the number of ordered unequal decimal digit pairs with `h|(b-a)` is

```text
W(h)=2*sum_{j=1}^{floor(9/h)}(10-h*j), if h<=9
W(h)=0, otherwise.
```

There are 90 ordered unequal pairs total. Consequently, a position is universally detecting iff `W(h)=0`, equivalently `h>9`. The minimum absolute undetected difference is `h` when `h<=9`; it is absent when `h>9`.

For `m=2^a*3^b*5^c*u`, `gcd(u,30)=1`, the stabilization position is `max(a,c)` for both classes. The stable values are `3^b*u` for substitutions and `3^max(b-2,0)*u` for transpositions. In the transposition gcd, the factor `3^min(b,2)` is present from the start: `10^k=2^k*5^k` introduces no additional factors of 3.

## API and returned quantities

Public functions and frozen result structures are exported from `modular_error_detection`:

- `reduced_divisor(modulus, coefficient, position)` implements `m/gcd(m,c*10^k)` using integer arithmetic.
- `ordered_unequal_digit_pair_count(h)` computes `W(h)`.
- `substitution_position_profile(modulus, position)` and `transposition_position_profile(modulus, position)` return `PositionProfile` values with `h`, pair counts, exact `Fraction` rates, universal-detection status, and minimum undetected difference when present.
- `substitution_length_profile(modulus, length)` and `transposition_length_profile(modulus, length)` return `LengthProfile` values containing per-position records and summed full-string event counts. The transposition function requires `length>=2` because there is no adjacent-pair position at length 1.
- `stabilization_position(modulus, error_class)` returns the first stable position; `stabilized_reduced_divisor(modulus, error_class)` returns the eventual reduced divisor.

Position-level digit-pair counts are distinct from full-string event counts. At each substitution position, total events are `90*10^(n-1)` and undetected events are `W(h_s)*10^(n-1)`. At each transposition position, total events are `90*10^(n-2)` and undetected events are `W(h_t)*10^(n-2)`. Length totals sum these position values. All returned rates are exact `Fraction` objects; no floating-point approximation is part of the core.

The rates are fractions under a uniform measure over the defined event set. They are not real-world error probabilities without a justified error distribution. Zero-event transposition at length 1 remains represented by no fixed-length transposition profile, rather than a zero rate.

## Computational validation

Tests check the gcd factorizations and reduced divisors for moduli 2, 3, 5, 9, 10, 11, 12, 18, 25, 30, and 31 at positions 0 through 3; known `W(h)` values; stabilization; universal-detection examples; exact fixed-length totals; and immutability of result records.

Focused cross-checks enumerate small fixed-width strings with the existing substitution and adjacent-transposition generators, then compare per-position and aggregate counts/rates with the analytical engine. This checks that the formulas and existing event generators agree for those selected cases; it is not a rerun of the historical sweep and does not prove the formulas for all parameters.

The historical sweep remains the separate finite experiment over moduli 2-30 and lengths 1-4. Its reports are not regenerated by the profile engine.

## Research interpretation

The engine packages the exact formulas as a reusable profile API. It provides position signatures and finite-length event counts rather than only pooled reports. This is a computational implementation of the established derivation, not a novelty claim. A behavioral equivalence of moduli can be defined by equality of the position signatures, but the value of presenting such classes as a research classification has not been established.
